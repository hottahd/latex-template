\chapter{修士論文を書くにあたって}
\label{chap:guide}

この章は、論文の中身ではなく書き方についての説明です。

\section{苦労したことではなく、結論につながることを書く}
\label{sec:guide_logic}

一番よくある失敗は、自分が苦労した順に書いてしまうことです。
「まずこれを試してうまくいかなかった、次にこうしたらこうなった、
それでパラメータを変えてみて……」という書き方です。
書いている本人にとっては、そこが研究で一番大変だったところなので、
どうしても書きたくなる気持ちはよく分かります。

ただ、論文として重要なのはそこではなく\textbf{何が新しく分かったのか}と、\textbf{なぜそう言えるのか}の二つです。

ですので、まず結論を決めてください。
そのうえで、その結論を導くために必要な論理を並べ、
その論理を支えるのに必要な材料を書きます。
結論につながらない作業は、どれだけ苦労したものであっても、
付録に回すか、思い切って落としましょう。

\section{イントロダクションは最後に書く}
\label{sec:guide_intro}

\textbf{イントロダクションは、全ての結果が揃ってから書いてください。}
結果ができる前に書いたイントロは、ほぼ確実に書き直しになります。

イントロダクションの役割は、読者を結論まで連れていくことです。
物語でいうと「フラグを立てる」作業です。
適切なフラグを立てておくと、読者は自然と結論まで連れていかれます。
そして\textbf{結論では、そのフラグを回収します}。
ですから、イントロと結論は必ず対応していなければいけません。

順番としては、
\begin{enumerate}
  \item 結果を全部出す
  \item 結果を主張するための図を作る
  \item 結果から言える結論を決める
  \item その結論へ連れていくためのイントロを書く
  \item 結論を、イントロで立てた問いへの答えの形に書き直す
\end{enumerate}
となります。

\section{章立て}
\label{sec:guide_structure}

章立ては以下のようなものが推奨されます。

\begin{description}
  \item[序論] 第\ref{sec:guide_intro}節のとおり。背景、これまでに分かっていること、まだ分かっていないこと、本研究の目的、論文の構成。
  \item[手法] 使ったモデルの説明。基礎方程式、計算領域、境界条件、初期条件、解像度、使ったコード。
  \item[結果] 得られた結果を順序立てて示します。ここでどれだけ議論するかは人によりますが、堀田はある程度の議論は結果の中でしてしまうことが多いです。
  \item[議論] 結果の解釈、先行研究との比較を示します。
  \item[結論] イントロで立てた問いへの答えを羅列します。何かまとめるような図(ポンチ絵)を作ってもいいでしょう。最後に今後の展望を書きます。
\end{description}

\section{図}
\label{sec:guide_figure}

図がわかりやすい論文は、読むのが楽になります。
逆に図が読めないと、本文をどれだけ丁寧に書いても読むのが困難です。

\subsection{印刷して確かめる}

\textbf{図を論文に貼り付けて、実際に印刷して、それでも読めるかを確かめてください。}画面の上では拡大すれば読めてしまうので、そこで判断しないでください。軸の数字、軸のラベル、凡例、カラーバーの目盛りが、
紙の上で読めるかどうかが基準です。

読めなければ、図を作る段階に戻って文字を大きくします。
\verb|\includegraphics| に \verb|width=0.5\linewidth| のように指定して
後から縮めると文字も一緒に縮むので、その分を見越して作ってください。
図の目盛りの字は特に小さくなりがちです。

どのくらいにすればよいか分からなければ、堀田の論文の図を見てください。
例えば \citet{hotta2022} の図が参考になります。
自分の図と並べて、軸の文字の大きさを比べてみるとよいでしょう。

\subsection{カラーバーを必ずつける}

色で量を表した図には、\textbf{必ずカラーバーをつけてください}。
何色がどのくらいの値なのかが分からないと、読む人は色の濃淡を眺めることしかできなくなってしまいます。カラーバーには単位も書きましょう。

\subsection{キャプション}

キャプションだけを読んで何の図かが分かる必要はありますが、\textbf{長すぎるキャプションは、読解を妨げますので、必要十分にとどめましょう}。軸の量と単位、線や色が何を表すか、どの計算のものか。これらが分かる最小限で書いてください。特に、異なる図の間で線種が同じ意味を持つ場合(例えば磁場入りの計算は赤、磁場なしは青と決める)は、凡例には毎回示すことは必要ですが、毎回キャプションに書く必要はありません。最初の図で説明すれば十分です。また、異なる図の間で、同じ色が使われるように注意しましょう。例えば、ある図で赤が磁場入りの計算を表すなら、次の図でも赤は磁場入りの計算を表すようにします。

\subsection{形式}

\begin{itemize}
  \item 折れ線・等高線・散布図などの線画は PDF で保存します。
    拡大しても線が滑らかで、印刷しても綺麗です。
    Matplotlib なら \verb|plt.savefig('foo.pdf')| とするだけです。非常に高解像度の場合も \verb|rasterized=True|を指定すると PDF に埋め込まれるので、PDF のまま提出できます。
  \item LuaLaTeX が読めるのは PDF・PNG・JPEG です。
    EPS は先に PDF に変換しておいてください。
\end{itemize}

\section{細かい約束事}
\label{sec:guide_manner}

論文の細かいルールを確認しましょう。

\subsection{数字と単位の間は半角 1 マス空ける}

\qty{1}{\km}、\qty{100}{\gram}、\qty{12}{\second} のように、
数字と単位の間は必ず半角 1 マス空けます。
\verb|%| は空ける必要がありません（天文業界では空けないことがほとんどです）。

必ず守ってください。このテンプレートでは \texttt{siunitx} を読み込んであるので、

\begin{verbatim}
太陽半径は \qty{6.96e10}{cm}、自転角速度は \qty{2.6e-6}{\per\second} です。
\end{verbatim}

\noindent
と書けば、空きは自動的に正しくなります。
従来どおり \verb|$2~\mathrm{km~s^{-1}}$| と手で書いても構いませんが、
論文全体でどちらかに統一してください。

\subsection{イタリック体とローマン体}

物理量として定義している文字（変数、定数）はイタリック体、
それ以外（単位、関数名など）はローマン体にします。
圧力 $p$ や速度 $v$ はイタリックです。

これは\textbf{特に添字のときに重要}です。
$F_\mathrm{rad}$ の \texttt{rad} は「radiation」の略なのでローマン体、
$F_v$ の $v$ は物理量なのでイタリック体です。
\LaTeX{} では前者を \verb|F_\mathrm{rad}|、後者を \verb|F_v| と書きます。
これも必ず守ってください。

\section{引用と剽窃}
\label{sec:guide_citation}

\textbf{引用は適切にしてください。剽窃は絶対にしないでください。}
ここだけは作法の問題ではなく、研究者として守らなければならない一線です。
剽窃が発覚すれば学位は取り消されます。

他人の文章・図・アイデアを、出典を示さずに自分のものとして
提示することはすべて剽窃です。以下はいずれも剽窃にあたります。

\begin{itemize}
  \item 論文や web の文章をコピーして貼り、少し語尾を変えて自分の文にする
  \item 他人の図を、出典を書かずに載せる
  \item 先輩の修士論文から章をまるごと持ってくる
  \item 自分の過去の文章を、断りなく再利用する（自己剽窃）
\end{itemize}

事実や知見を借りるときは、自分の言葉で書き直して引用をつけます。
「対流層の底は $0.71\,R_\odot$ にある \citep{christensen-dalsgaard1991}」
のように書きます。

図を借りるときは、キャプションの末尾に出典を書きます。
「\citet{hotta2022} の Figure 3 を改変」のように書いてください。
商業出版社の論文の図は、多くの場合、著者本人であっても転載に許諾が要ります。論文の web ページにある \textsf{Permissions} や \textsf{RightsLink} から手続きしてください。許諾が取れないなら、自分で描き直します。

なお、都合の悪い点を消す、エラーバーを小さく見せる、軸を切って差を大きく見せる、といった操作は捏造・改竄です。処理を加えたなら、加えたことを本文に書いてください。「見やすさのために平滑化した」と一言書いておけば何の問題もありません。書かずにやってしまうと不正になります。

\section{AI との付き合い方}
\label{sec:guide_ai}

AI については別に文章を書いているので、そちらを読んでください。

\begin{center}
  \url{https://hotta.notion.site/AI-3a604f9ef588804f92dceed12fcb99b7}
\end{center}

\noindent
論文を書くときに関係するところだけ、ここに繰り返しておきます。

私は、AI は積極的に使ってほしいと思っています。
英語の推敲、書き出しに詰まったときの相談、論文を読むときの補助など、
うまく使えばできることは大きく増えます。

そのうえで、コードについて言っているのと同じことが文章にも当てはまります。
\textbf{AI が出した文章は、自分が納得するまで説明させてください。}
説明を聞いても理解できない部分が残るなら、その文章はまだ自分の文章ではありません。自分で説明できない文章は、論文に載せないでください。

引用文献については特に注意してください。
AI は存在しない論文を、もっともらしい形式で出してくることがあります。
\textbf{引用する論文は必ず ADS で実在を確かめてください。}

AI をどう使ったか、何がうまくいったかは、ぜひ教えてください。
私自身も Claude Code や Codex を使っていて、良い使い方を探している最中です。一緒に考えましょう。

また、AIについての大学の考え方もまだ固まっていないと思います。今後、学位論文にはAIは一切使ってはいけないという方針になる可能性もあります。その場合は、この文章ではなく、大学の方針に従ってください。

\section{添削の受け方}
\label{sec:guide_review}

\subsection{Overleaf で完結させる}

原稿の添削は研究室の Overleaf の中で完結します。
メールで \texttt{.tex} を往復させる必要はありません。
使い方は研究グループの Loop に案内があるので、そちらを見てください。

\subsection{執筆計画}

総合解析研究部では、12月末に研究部内部での教員のレビューをおこないます。それまでに、堀田が皆さんの論文をレビューする必要があるので、最初の目標は12月1日の私への提出です。少なくとも2ヶ月は論文執筆にかかると考えると10月には書き始める必要があります。

\section{\LaTeX{} の使い方}
\label{sec:guide_latex}

\subsection{このテンプレートの構成}

自分で書き換えるのは次の 3 つだけです。

\begin{description}
  \item[\texttt{main.tex}] 表紙に載る情報、概要、章の並び。
  \item[\texttt{body.tex}] 本文。序論から結論まで。
  \item[\texttt{thesis.bib}] 引用文献。
  \item[\texttt{fig/}] 図を置くところ。
\end{description}

\noindent
残りは触らなくて構いません。

\begin{description}
  \item[\texttt{preamble.tex}] パッケージと設定。
    余白や参考文献の形式を変えたくなったときだけ開いてください。
  \item[\texttt{achilles.sty}] 全テンプレート共通のプリアンブル。
  \item[\texttt{thesiscover.sty}] 表紙のレイアウト。
  \item[\texttt{guide.tex}] この章。書き終わったら \verb|\input{guide}| を外します。
  \item[\texttt{guide-only.tex}] この章だけの PDF を作るためのものです。
    \verb|latexmk guide-only.tex| としてください。
\end{description}

\noindent
\texttt{body.tex}、\texttt{guide.tex}、\texttt{preamble.tex} は
\verb|\documentclass| を持たない断片なので、単体ではコンパイルできません。
間違えて叩いたときは、その旨を出して止まります。

\subsection{コンパイル}

このディレクトリで
\begin{verbatim}
latexmk
\end{verbatim}
とすれば \texttt{main.pdf} ができます。書きながら自動で作り直したいときは
\verb|latexmk -pvc| とします。
中間ファイルがおかしくなったら \verb|latexmk -C| で全部消してやり直してください。
エンジンは LuaLaTeX です。\texttt{platex} や \texttt{uplatex} では通りません。

\subsection{相互参照}

図・表・式・章には \verb|\label{}| をつけ、本文からは \verb|\ref{}| で参照します。番号を手で書かないでください。あとで章を入れ替えたときに合わなくなります。
ラベルには \verb|fig:|、\verb|tab:|、\verb|eq:|、\verb|sec:|、\verb|chap:| の
接頭辞をつけると分かりやすくなります。

\begin{verbatim}
図\ref{fig:sample}に示すように……
式\eqref{eq:induction}より……
\end{verbatim}

\noindent
式の参照は \verb|\ref| ではなく \verb|\eqref| を使うと括弧がつきます。

\subsection{引用}

\texttt{thesis.bib} に文献情報を書き、本文から \verb|\citep| か \verb|\citet| で引きます。
NASA ADS の \textsf{Export Citation} から \textsf{BibTeX} を選べば、そのまま貼り付けられる形式で得られます。手で打ち直さないでください。

\begin{verbatim}
小スケールダイナモが有効粘性を下げる \citep{hotta2021}。
\citet{hotta2021} はこれを高解像度計算で示した。
\end{verbatim}

\subsection{数式}

番号をつけて後で参照する式は \texttt{align}、参照しない式は \texttt{align*} を使います。
\verb|$$ ... $$| は使わないでください（前後の空きがおかしくなります）。
ベクトルは \verb|\bm{B}| と書くと太字斜体になります（\texttt{bm} パッケージ）。
それ以外に独自のコマンドは用意していません。
\verb|\nabla\cdot| や \verb|\frac{\partial f}{\partial x}| を
そのまま書いてください。ここだけで通じる書き方を覚えても、
他所で論文を書くときには使えないためです。

\subsection{よくあるつまずき}

\begin{description}
  \item[エラーが出たら一番上から読む] 後ろのエラーは前のエラーの巻き添えであることが多いです。\texttt{main.log} で最初の \verb|.tex:行番号:| を探してください。エラーを丸ごとAIに渡すのが2025年頃からは良いでしょう。
\end{description}

\section{提出前の確認}
\label{sec:guide_checklist}

\begin{itemize}
  \item 表紙の年度・題目・氏名・学籍番号・所属が、学務に出す書類と一致しているか
  \item イントロと結論が対応しているか
  \item 図を印刷して、軸の文字とカラーバーが読めるか
  \item 数字と単位の間が空いているか
  \item 添字のローマン体・イタリック体が正しいか
  \item 図がすべて本文から参照されているか
  \item 引用文献が本文の引用とすべて対応しているか
  \item この章を \texttt{main.tex} から外したか
  \item 行番号（\texttt{lineno}）を切ったか
\end{itemize}
