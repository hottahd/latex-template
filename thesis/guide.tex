\chapter{修士論文を書くにあたって}
\label{chap:guide}

この章は、論文の中身ではなく書き方についての説明です。
学生の皆さんの原稿を読んでいると、毎年ほとんど同じことを指摘していることに
気づいたので、文章にしました。書き始める前に一度読んでください。

以下は堀田の考えが多く含まれているので、全ての人に当てはまるわけではありません。
それでも、私と一緒に論文を書いている間は、参考にしてもらえると嬉しいです。

先に言っておくと、論文を書くのは大変です。私も毎回大変です。
最初からうまく書ける人はいないので、うまくいかなくても落ち込まないでください。

\section{苦労したことではなく、結論につながることを書く}
\label{sec:guide_logic}

一番よくある失敗は、自分が苦労した順に書いてしまうことです。
「まずこれを試してうまくいかなかった、次にこうしたらこうなった、
それでパラメータを変えてみて……」という書き方です。
書いている本人にとっては、そこが研究で一番大変だったところなので、
どうしても書きたくなる気持ちはよく分かります。私も学生の頃はそうでした。

ただ、読む人が知りたいのは残念ながらそこではなく、
\textbf{何が新しく分かったのか}と、\textbf{なぜそう言えるのか}の二つです。

ですので、まず結論を決めてください。
そのうえで、その結論を導くために必要な論理を並べ、
その論理を支えるのに必要な材料だけを書きます。
結論につながらない作業は、どれだけ苦労したものであっても、
付録に回すか、思い切って落としましょう。
これができているかどうかで、論文の読みやすさは全く変わります。

苦労した部分を落とすのは、正直つらいと思います。
しかし、何が要って何が要らないかを自分で判断できるようになること自体が、
研究者としての大きな進歩です。

どうしても残したい場合は、付録に書いてください。
付録は「本文の論理には要らないが、あとから同じことをやる人には要る」ものを
置く場所です。試行錯誤の記録は、まさにそこに向いています。

\section{イントロダクションは最後に書く}
\label{sec:guide_intro}

これも毎年言っています。

\textbf{イントロダクションは、全ての結果が揃ってから書いてください。}
結果ができる前に書いたイントロは、ほぼ確実に書き直しになります。

イントロダクションの役割は、読者に結論を聞きたいと思わせるための準備です。
物語でいうと「フラグを立てる」作業です。
適切なフラグを立てておくと、読者は自然と結論まで連れていかれます。
そして\textbf{結論では、そのフラグを回収します}。
ですから、イントロと結論は必ず対応していなければいけません。

順番としては、
\begin{enumerate}
  \item 結果を全部出す
  \item 結果から言える結論を決める
  \item その結論が「なるほど」と思われるようなイントロを書く
  \item 結論を、イントロで立てた問いへの答えの形に書き直す
\end{enumerate}
となります。

しばしば、最初に堀田が与えたテーマのイントロに引っ張られたまま
書き進めてしまう学生がいます。
指導教員も研究の最後までを見通せているわけではありません。
研究をしていくうちに、当初考えていたのとは違うことが面白くなっている、
ということはよく起こります。そうなったら、イントロは全部書き直してください。
自分の結果を一番よく理解しているのは、あなたです。

例えば「恒星の巨大黒点の時間発展を追う」という研究を始めたとします。
当初は黒点の寿命の、大きさや恒星の種類への依存性を調べる予定でした。
その場合のイントロは「宇宙には色々な恒星があり、色々な黒点が現れる。
それぞれについて黒点の寿命を求めたい」と始めればよいでしょう。
ところが計算をしてみると「黒点の出現する緯度によって、
同じ恒星でも寿命が大きく違う」ということが分かったとします。
このときは、イントロを大きく変えて
「観測から黒点の寿命を測ることが可能になってきた。
この寿命の観測から、黒点の出現緯度が推測できるのではないか」
と始めるのが良いということになります。

もう一つ、\textbf{イントロで喋りすぎないでください}。
上の例で「恒星には色々な種類があり、それは質量によっていて、
内部の核融合反応が違い、内部構造はこうなっていて……」と書き始めると、
論文と関係のない話が延々と続くことになります。
イントロに書くのは、その論文を理解するために必要な前提知識だけです。
修士論文は勉強したことの発表会ではありません。

\section{章立て}
\label{sec:guide_structure}

我々のところはほとんどが数値シミュレーションの研究なので、
次の章立てにしましょう。

\begin{description}
  \item[序論] 第\ref{sec:guide_intro}節のとおり。背景、これまでに分かっていること、
    まだ分かっていないこと、本研究の目的、論文の構成。
  \item[手法] 使ったモデルの説明。基礎方程式、計算領域、境界条件、初期条件、
    解像度、使ったコードとそのバージョン。
    \textbf{他人が読んで同じ計算を再現できるか}が唯一の基準です。
    「標準的な手法を用いた」で済ませないでください。
    何が標準かは 10 年で変わります。
  \item[結果] 何が見えたかだけを書きます。解釈は次の章です。
    ただし図の説明を機械的に並べるのではなく、
    読者が図を見る順番を案内するつもりで書いてください。
  \item[議論] 結果の解釈、先行研究との比較、そして本研究の限界。
    限界を書くのを怖がらないでください。
    自分で把握できていることは減点ではなく加点です。
    審査で指摘されて初めて気づくのが一番まずいです。
  \item[結論] イントロで立てた問いへの答えを短く言い切ります。
    ここで新しい図やデータを出してはいけません。
    最後に今後の展望を 1 段落だけ書きます。
\end{description}

\section{図}
\label{sec:guide_figure}

審査員は本文より先に図を見ます。図が分かりやすければ、論文は半分伝わったも同然です。
逆に図が読めないと、本文をどれだけ丁寧に書いても伝わりません。

\subsection{印刷して確かめる}

これも毎年言っています。
\textbf{図を論文に貼り付けて、実際に印刷して、それでも読めるかを確かめてください。}
画面の上では拡大すれば読めてしまうので、そこで判断しないでください。
軸の数字、軸のラベル、凡例、カラーバーの目盛りが、
紙の上で読めるかどうかが基準です。

読めなければ、図を作る段階に戻って文字を大きくします。
\verb|\includegraphics[width=0.5\linewidth]| のように後から縮めると
文字も一緒に縮むので、その分を見越して作ってください。
図の目盛りの字は特に小さくなりがちです。

どのくらいにすればよいか分からなければ、堀田の論文の図を見てください。
例えば \citet{hotta2022} の図が参考になります。
自分の図と並べて、軸の文字の大きさを比べてみるとよいでしょう。

\subsection{カラーバーを必ずつける}

色で量を表した図には、\textbf{必ずカラーバーをつけてください}。
何色がどのくらいの値なのかが分からないと、
読む人は色の濃淡を眺めることしかできなくなってしまいます。
カラーバーには単位も書きましょう。

\subsection{キャプションは短く}

キャプションだけを読んで何の図かが分かる必要はありますが、
\textbf{長すぎるキャプションは、私はあまり好きではありません}。
軸の量と単位、線や色が何を表すか、どの計算のものか。
これらが分かる最小限で書いてください。
説明したいことが増えてきたら、それは本文に書くべき内容です。

なお、軸が何であるかは\textbf{本文でも必ず説明してください}。
図に書いてあるから分かるだろう、と思いたくなりますが、
読む人は意外とついてこられません。

\subsection{形式}

\begin{itemize}
  \item 折れ線・等高線・散布図などの線画は PDF で保存します。
    拡大しても線が滑らかで、印刷しても綺麗です。
    Matplotlib なら \verb|plt.savefig('foo.pdf')| とするだけです。
  \item 太陽表面の強度分布のような画素の塊は PNG にします。
    PDF にすると数十 MB になり、PDF ビューアが固まります。
    \verb|dpi=300| 程度あれば印刷に耐えます。
  \item LuaLaTeX が読めるのは PDF・PNG・JPEG です。
    EPS は先に PDF に変換しておいてください。
\end{itemize}

\section{細かい約束事}
\label{sec:guide_manner}

細かいことですが、揃っていないと読む人がそちらに気を取られて、
肝心の中身を読んでもらえなくなります。
どれも一度覚えれば済むことなので、ここで覚えてしまいましょう。

\subsection{数字と単位の間は半角 1 マス空ける}

\qty{1}{\km}、\qty{100}{\gram}、\qty{12}{\second} のように、
数字と単位の間は必ず半角 1 マス空けます。
\verb|%| は空ける必要がありません（天文業界では空けないことがほとんどです）。

これは大学院生になっても抜けやすいところです。私も学生の頃はよく直されました。
必ず守ってください。
このテンプレートでは \texttt{siunitx} を読み込んであるので、

\begin{verbatim}
太陽半径は \qty{6.96e8}{m}、自転角速度は \qty{2.6e-6}{\per\second} です。
範囲を書くときは \qtyrange{1}{5}{\km\per\second} とします。
\end{verbatim}

\noindent
と書けば、空きは自動的に正しくなります。
従来どおり \verb|$2~\mathrm{km~s^{-1}}$| と手で書いても構いませんが、
論文全体でどちらかに統一してください。

\subsection{イタリック体とローマン体}

物理量として定義している文字（変数、定数）はイタリック体、
それ以外（単位、関数名など）はローマン体にします。
圧力 $p$ や速度 $v$ はイタリックです。

これは\textbf{特に添字のときに重要}です。
$F_\mathrm{rad}$ の \texttt{rad} は「radiation」の略なのでローマン体、
$F_v$ の $v$ は物理量なのでイタリック体です。
\LaTeX{} では前者を \verb|F_\mathrm{rad}|、後者を \verb|F_v| と書きます。
これも必ず守ってください。

\subsection{有効数字}

計算機が出した 8 桁をそのまま書き写さないでください。
測定や計算の精度に見合った桁数にします。

\subsection{用語を統一する}

「対流セル」と「対流構造」を無意識に混ぜないでください。
同じものは同じ語で呼び、違うものは違う語で呼びます。

\section{引用と剽窃}
\label{sec:guide_citation}

\textbf{引用は適切にしてください。剽窃は絶対にしないでください。}
ここだけは作法の問題ではなく、研究者として守らなければならない一線です。
剽窃が発覚すれば学位は取り消されます。

他人の文章・図・アイデアを、出典を示さずに自分のものとして
提示することはすべて剽窃です。以下はいずれも剽窃にあたります。

\begin{itemize}
  \item 論文や web の文章をコピーして貼り、少し語尾を変えて自分の文にする
  \item 他人の図を、出典を書かずに載せる
  \item 先輩の修士論文から章をまるごと持ってくる
  \item 自分の過去の文章を、断りなく再利用する（自己剽窃）
\end{itemize}

事実や知見を借りるときは、自分の言葉で書き直して引用をつけます。
「対流層の底は $0.71\,R_\odot$ にある \citep{christensen-dalsgaard1991}」
のように書きます。

どこまで自分の言葉にすればよいかの基準は、
語順を入れ替えたか同義語に置き換えたかではありません。
\textbf{元の文章を見ずに、理解した内容を自分で書けるか}です。
見ないと書けないなら、まだ自分のものになっていないということなので、
もう一度読み直してみてください。

図を借りるときは、キャプションの末尾に出典を書きます。
「\citet{hotta2022} の Figure 3 を改変」のように書いてください。
商業出版社の論文の図は、多くの場合、著者本人であっても転載に許諾が要ります。
論文の web ページにある \textsf{Permissions} や \textsf{RightsLink} から
手続きしてください。許諾が取れないなら、自分で描き直します。

なお、都合の悪い点を消す、エラーバーを小さく見せる、
軸を切って差を大きく見せる、といった操作は捏造・改竄です。
処理を加えたなら、加えたことを本文に書いてください。
「見やすさのために平滑化した」と一言書いておけば何の問題もありません。
書かずにやってしまうと不正になります。

\section{AI との付き合い方}
\label{sec:guide_ai}

AI については別に文章を書いているので、そちらを読んでください。

\begin{center}
  \url{https://hotta.notion.site/AI-3a604f9ef588804f92dceed12fcb99b7}
\end{center}

\noindent
論文を書くときに関係するところだけ、ここに繰り返しておきます。

私は、AI は積極的に使ってほしいと思っています。
英語の推敲、書き出しに詰まったときの相談、論文を読むときの補助など、
うまく使えばできることは大きく増えます。

そのうえで、コードについて言っているのと同じことが文章にも当てはまります。
\textbf{AI が出した文章は、自分が納得するまで説明させてください。}
説明を聞いても理解できない部分が残るなら、その文章はまだ自分の文章ではありません。
自分で説明できない文章は、論文に載せないでください。
審査で聞かれるのは論文そのものではなく、書いた本人だからです。

引用文献については特に注意してください。
AI は存在しない論文を、もっともらしい形式で出してくることがあります。
\textbf{引用する論文は必ず ADS で実在を確かめてください。}

AI をどう使ったか、何がうまくいったかは、ぜひ教えてください。
私自身も Claude Code や Codex を使っていて、良い使い方を探している最中です。
一緒に考えましょう。

\section{添削の受け方}
\label{sec:guide_review}

\subsection{Overleaf で完結させる}

原稿の添削は研究室の Overleaf の中で完結します。
メールで \texttt{.tex} を往復させる必要はありません。
使い方は別に案内があるので、そちらを見てください。

お願いすることは一つだけです。
\textbf{「ここまで書きました」という版にラベルを付けて、連絡してください。}
ラベルは \texttt{review-hotta} のように、\texttt{用途-相手} の形で付けます。
日付は要りません。履歴の画面が日時を表示してくれます。

ラベルさえ付いていれば、そこから後に何を直したかは自動的に分かります。
改訂のたびに別名で保存したり、変更箇所を報告したりする必要はありません。
以前は \texttt{latexdiff} で差分の PDF を作ってもらっていましたが、
日常の添削ではもう不要です。
差分の PDF が要るのは、雑誌への再投稿で
「変更箇所を明示した原稿」を求められたときだけです。

\textbf{私が付けたコメントや提案は、自分で承認・却下しないでください。}
対応した内容の確認に使いますので、そのまま残しておいてください。
返答したいことがあれば、コメントに返信する形で書けます。

\subsection{早く出す}

完璧になってから見せようとすると、たいてい間に合いません。
構成だけの段階、章ごと、と何度も出したほうが結果的に速く終わります。
中途半端でも構わないので、恥ずかしがらずに出してください。

\subsection{出す前に自分でやること}

自分で見つけられる誤りを先に潰しておくと、
添削の時間をまるごと中身の議論に使えます。
出す前に次を確かめておいてください。

\begin{itemize}
  \item \verb|\todo| と \verb|\red| が残っていないか検索する
  \item \texttt{??} や \texttt{[?]} が PDF に出ていないか確認する
  \item 図がすべて本文から参照されているか確認する
  \item 図を印刷して、軸の文字が読めるか確認する
  \item 数式の記号がすべて本文で定義されているか確認する
  \item 通しで一度、声に出して読む。黙読よりずっと効きます
\end{itemize}

\subsection{指摘の理由を考える}

直せと言われた箇所だけを直すと、同じ種類の誤りが他の場所に残ったままに
なりがちです。なぜそう指摘されたのかを考えて、
似た箇所をまとめて直すと、次の版がぐっと良くなります。

指摘が間違っていることもあります。
納得できないときは聞いてください。
黙って従うのも、黙って無視するのも良くありません。
自分が「こう」と思うなら、その思いを貫き通してくれて構いません。

\section{\LaTeX{} の使い方}
\label{sec:guide_latex}

\subsection{このテンプレートの構成}

\begin{description}
  \item[\texttt{main.tex}] 設定、表紙に載る情報、概要、章の並び。
    書き換えるのは主にこのファイルの上半分です。
  \item[\texttt{body.tex}] 本文。序論から結論まで。
  \item[\texttt{guide.tex}] この章。書き終わったら \verb|\input{guide}| を外します。
    \texttt{body.tex} と同じく本文の断片なので、単体ではコンパイルできません。
    この章だけの PDF が欲しいときは \verb|latexmk guide-only.tex| としてください。
  \item[\texttt{thesis.bib}] 引用文献。
  \item[\texttt{achilles.sty}] 全テンプレート共通のプリアンブル。
  \item[\texttt{thesiscover.sty}] 表紙のレイアウト。触らなくて構いません。
  \item[\texttt{fig/}] 図を置くところ。
\end{description}

\subsection{コンパイル}

このディレクトリで
\begin{verbatim}
latexmk
\end{verbatim}
とすれば \texttt{main.pdf} ができます。書きながら自動で作り直したいときは
\verb|latexmk -pvc| とします。
中間ファイルがおかしくなったら \verb|latexmk -C| で全部消してやり直してください。
エンジンは LuaLaTeX です。\texttt{platex} や \texttt{uplatex} では通りません。

\subsection{相互参照}

図・表・式・章には \verb|\label{}| をつけ、本文からは \verb|\ref{}| で参照します。
番号を手で書かないでください。あとで章を入れ替えたときに必ず合わなくなります。
ラベルには \verb|fig:|、\verb|tab:|、\verb|eq:|、\verb|sec:|、\verb|chap:| の
接頭辞をつけると分かりやすくなります。

\begin{verbatim}
図\ref{fig:sample}に示すように……
式\eqref{eq:induction}より……
\end{verbatim}

\noindent
式の参照は \verb|\ref| ではなく \verb|\eqref| を使うと括弧がつきます。

\subsection{引用}

\texttt{thesis.bib} に文献情報を書き、本文から \verb|\citep| か \verb|\citet| で引きます。
NASA ADS の \textsf{Export Citation} から \textsf{BibTeX} を選べば、
そのまま貼り付けられる形式で得られます。手で打ち直さないでください。

\begin{verbatim}
小スケールダイナモが有効粘性を下げる \citep{hotta2021}。
\citet{hotta2021} はこれを高解像度計算で示した。
\end{verbatim}

\subsection{数式}

番号をつけて後で参照する式は \texttt{align}、参照しない式は \texttt{align*} を使います。
\verb|$$ ... $$| は使わないでください（前後の空きがおかしくなります）。
ベクトルは \verb|\vect{B}| と書くと太字斜体になります。
\verb|\grad|、\verb|\divergence|、\verb|\curl|、\verb|\pdif{}{}| などの
短縮マクロを \texttt{achilles.sty} に用意してあります。

\subsection{よくあるつまずき}

\begin{description}
  \item[エラーが出たら一番上から読む] 後ろのエラーは前のエラーの巻き添えである
    ことが多いです。\texttt{main.log} で最初の \verb|.tex:行番号:| を探してください。
  \item[Undefined control sequence] マクロの綴りが違うか、
    必要なパッケージを読み込んでいません。
  \item[Overfull \textbackslash hbox] 行がはみ出しています。長い英単語や URL が原因です。
    数 pt なら無視して構いませんが、目で見て飛び出していたら直します。
  \item[番号が \texttt{??} になる] 参照が解決していません。もう一度コンパイルしてください
    （\texttt{latexmk} なら自動でやります）。それでも直らないならラベルの綴り間違いです。
  \item[図が出ない] ファイル名か拡張子が違います。
\end{description}

\section{提出前の確認}
\label{sec:guide_checklist}

\begin{itemize}
  \item 表紙の年度・題目・氏名・学籍番号・所属が、学務に出す書類と一致しているか
  \item イントロと結論が対応しているか
  \item 図を印刷して、軸の文字とカラーバーが読めるか
  \item 数字と単位の間が空いているか
  \item 添字のローマン体・イタリック体が正しいか
  \item 図がすべて本文から参照されているか
  \item 引用文献が本文の引用とすべて対応しているか
  \item この章を \texttt{main.tex} から外したか
  \item 行番号（\texttt{lineno}）を切ったか
  \item 印刷して提出するなら、リンクの色を黒にしたか
\end{itemize}
